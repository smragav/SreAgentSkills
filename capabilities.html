Where the native Azure tool is the better answer

Say this part out loud in the room. It is the fastest way to be believed on everything above it.

  • Enforcement belongs to Azure Policy. These skills measure and recommend, and they never enforce. The tag compliance skill says so in its own checks catalog and points at Policy as the durable fix. Treat the findings as the shortlist of what to turn into policy.
  • Threat detection belongs to Microsoft Defender for Cloud. Nothing here watches runtime behaviour, scans a container image, or detects an attack in progress. The security skills read configuration, not activity.
  • Retirement dates belong to Azure Service Health and the Azure roadmap. The deprecation tracker ships a built in list so it can rank your resources today, and its own catalog tells you to corroborate the specific dates before committing to one.
  • Billing truth belongs to Cost Management. The FinOps skill queries it rather than replacing it, and it treats Azure Advisor's cost recommendations as the baseline so savings are not double counted.
  • Standing privilege is fixed by Microsoft Entra PIM. The identity skill finds the Owner sprawl and the classic administrators. Just in time elevation and recurring access reviews are the actual remedy.
  • Always on scanning belongs to Advisor and Defender. They run whether anyone asks or not. These skills run on demand or on a schedule you set, which is the right shape for a change gate or an incident, and the wrong shape for continuous monitoring.
Access and trust model

The first question a security team asks is what this thing can do to their estate. The answer is nothing. There is no write tool, no delete tool, and no role assignment tool anywhere in the suite.

Reader, and nothing more

Every skill runs on the agent's default Reader access. None require an additional role assignment to start. Coverage equals the agent's read scope: a subscription outside that scope is simply not seen, and widening it is a separate administrative action.

It asks, it never grants

If a specific read is denied, a skill may ask a person to grant temporary, time bound access, explain what it needs and why, and then wait. It never performs the role assignment itself. Granting is always the user's action, done out of band through PIM or a temporary assignment.

A denial is a finding, not a failure

If access is declined, the skill skips that check, records it in the report as not assessed because of insufficient access, and continues with everything it can read. A gap in coverage is always visible in the output rather than silently absorbed.

Two data planes need their own read role

Key Vault certificate and secret metadata needs Key Vault Reader or a data plane list permission. Application credential expiry needs a Microsoft Graph directory read. Both are read only, both are named in the relevant checks catalog, and both degrade to not assessed when denied.

The identity trap, and the fix

An agent often carries a system assigned identity alongside the user assigned one, and the runtime can resolve to the system assigned identity, which is commonly created with no role assignments at all. Resource Graph answers that caller with HTTP 200 and a nearly empty result rather than an error, so a skill could report confidently on an estate it never saw.

Measured, not theoretical

On one agent, the system assigned identity saw 15 resources where the user assigned identity saw 1140. The shared tools/agent_identity.py removes that failure mode: it reads the agent resource named in its own token, finds the attached user assigned identity, and authenticates as that. This is why every skill bundles the shared tools.

Reads used, all covered by Reader
  • Subscription enumeration: the list of subscriptions the identity can see.
  • Resource enumeration through Azure Resource Graph, which reads across every accessible subscription in one query.
  • Azure Monitor metrics, alert rules, action groups, and diagnostic settings.
  • Azure Resource Health and Service Health advisories.
  • Azure Advisor recommendations.
  • Resource provider read endpoints on Azure Resource Manager, for example Key Vault properties, backup vault items, and quota usage.
The rule every skill keeps

Read only throughout. A skill proposes recommendations and provides operator ready commands, but a human reviews and runs anything that changes or deletes a resource. The agent runs none of them.
